# Результаты M0 Discovery Avito

Дата исследования: 2026-06-17.

Цель: проверить, можно ли использовать Avito как источник данных для будущего модуля мониторинга цен.

Связанный план:

- `docs/18_avito_data_source_discovery.md`.

## 1. Итоговое Решение

Текущий статус: `hold`.

Причины:

- в официальном каталоге API Avito не найден явно открытый API для поиска публичных рыночных объявлений по текстовому запросу;
- официальный раздел API "Объявления" относится к объявлениям авторизованного пользователя, статистике, продвижению и обновлению цены своих объявлений;
- условия использования Avito API для бизнеса описывают API как интерфейс для управления объявлениями пользователя на Avito;
- простой HTML-запрос к публичной поисковой выдаче Avito с сервера получил `HTTP 429` и страницу "Доступ ограничен: проблема с IP" с CAPTCHA;
- `robots.txt` содержит ограничения для ряда поисковых и технических URL, включая `/?q=`, `/q/*`, `/api/`, `/web/`.

Вывод: начинать разработку БД, UI и дашбордов модуля пока нельзя. Сначала нужно принять решение по источнику данных: официальный доступ через Avito/партнёра или отдельный согласованный parsing-подход.

## 2. Проверенные Официальные Источники

Проверены:

- портал разработчика Avito: `https://developers.avito.ru/`;
- каталог API: `https://developers.avito.ru/api-catalog`;
- JSON списка API-разделов: `https://developers.avito.ru/web/1/openapi/list`;
- JSON OpenAPI раздела "Объявления": `https://developers.avito.ru/web/1/openapi/info/item`;
- страница "Зачем нужен API": `https://developers.avito.ru/about-api`;
- условия использования API: `https://developers.avito.ru/docs/APITermsOfServiceV1.pdf`;
- robots.txt: `https://www.avito.ru/robots.txt`.

Официальный каталог API содержит разделы:

Раздел `item` называется "Объявления", но его описание:

```text
API для получение статистики по объявлениям, применения дополнительных услуг,
а также просмотр статусов объявлений
```

Фактические endpoint-ы раздела `item`:

```text
/core/v1/accounts/{userId}/vas/prices
/core/v1/accounts/{user_id}/calls/stats/
/core/v1/accounts/{user_id}/items/{item_id}/
/core/v1/accounts/{user_id}/items/{item_id}/vas
/core/v1/items
/core/v1/items/{item_id}/update_price
/core/v2/accounts/{user_id}/items/{item_id}/vas_packages
/core/v2/items/{itemId}/vas/
/stats/v1/accounts/{user_id}/items
/stats/v2/accounts/{user_id}/items
/stats/v2/accounts/{user_id}/spendings
```

Ключевые наблюдения:

- `/core/v1/items` возвращает список объявлений авторизованного пользователя;
- `/core/v1/items/{item_id}/update_price` обновляет цену своего объявления;
- `/stats/.../items` отдаёт статистику по объявлениям пользователя;
- методов поиска публичных объявлений по тексту, категории и региону в `item` не найдено.

Во всём списке OpenAPI-разделов найденные методы поиска относятся к другим доменам:

- `job` - поиск резюме и вакансий;
- `realty-reports` - отдельный метод соответствия цены рыночной цене для недвижимости, доступный только при активной подписке "Лидер" в категории "Недвижимость".

Для оборудования и товаров публичный search API в проверенном каталоге не найден.

## 4. Условия Использования API

В PDF "Условия использования Avito API для бизнеса" указано, что API даёт возможность создавать приложения, напрямую взаимодействующие с Avito, для управления объявлениями пользователя на Avito.

В разделе возможностей API перечислены:

- получение данных отчётов об автозагрузке объявлений;
- просмотр статистики и других данных по своим объявлениям;
- направление заявок на применение платных услуг к объявлениям.

Это подтверждает, что публичный API в текущей проверке ориентирован на работу со своими объявлениями, а не на мониторинг чужой рыночной выдачи.

## 5. Результат HTML Parsing Spike

Проверочный запрос:

```text
https://www.avito.ru/all?q=Kyocera%20ECOSYS%20M2040dn
```

Результат:

```text
HTTP/2 429
server: QRATOR
title: Доступ ограничен: проблема с IP
CAPTCHA: присутствует
```

В HTML ответа обнаружены:

- текст "Доступ ограничен: проблема с IP";
- hCaptcha;
- внутренний captcha-блок;
- GeeTest captcha;
- форма проверки.

Минимальные данные объявлений не получены:

- цена: нет;
- ссылка: нет;
- заголовок: нет;
- регион: нет;
- внешний ID объявления: нет.

Вывод по простому `requests`/`curl` подходу: с текущего серверного IP публичная поисковая выдача недоступна, запрос упирается в антибот-защиту.

## 6. robots.txt

В блоке `User-agent: *` обнаружены ограничения:

```text
Disallow: /?q=
Disallow: /q/*
Disallow: /api/
Disallow: /web/
Disallow: /autosearch/
Disallow: /search/filters/
```

Это не является полноценной юридической экспертизой, но для проекта это существенный сигнал риска. Автоматический сбор поисковой выдачи требует отдельного согласования и аккуратной правовой оценки.

## 7. Оценка Вариантов

### API

Статус: не подтверждён.

Плюсы:

- официальный механизм;
- лучше для промышленной эксплуатации;
- меньше технических рисков.

Минусы:

- в публичном каталоге не найден метод поиска чужих объявлений по товарам/оборудованию;
- API "Объявления" работает вокруг своих объявлений;
- вероятно нужен отдельный запрос в поддержку или партнёрский доступ.

### HTML-Парсинг

Статус: простой подход не прошёл.

Плюсы:

- если будет допустим и технически решён, может дать именно рыночную выдачу.

Минусы:

- текущий сервер получил `HTTP 429`;
- включается CAPTCHA;
- HTML Avito нестабилен;
- есть ограничения в robots;
- нельзя закладывать обход CAPTCHA, rate limits или блокировок.

### Ручной / CSV-Источник

Статус: fallback, не целевой механизм.

Плюсы:

- можно проверить отчёты без внешнего риска.

Минусы:

- не решает главную цель ежедневного автоматического мониторинга;
- не должен быть основанием для разработки основного модуля без решения по Avito.

## 8. Go / No-Go

Текущий результат: `hold`.

Не `go_api`, потому что:

- публичный API поиска рыночных объявлений по товарам не найден.

Не `go_parsing`, потому что:

- простой HTML-запрос уже получил 429/CAPTCHA;
- минимальный набор данных объявлений не извлечён;
- допустимость такого сбора не подтверждена.

Не `no_go`, потому что:

- остаётся возможность запросить у Avito официальный/партнёрский доступ;
- остаётся возможность отдельного согласованного parsing-подхода, если бизнес и юристы его допустят;
- можно уточнить сценарий через поддержку Avito.

## 9. Рекомендации

### 1. Написать В Поддержку Avito

Нужно задать прямой вопрос:

```text
Нужен официальный способ ежедневно получать цены публичных объявлений Avito
по 100-200 поисковым запросам для внутренней аналитики рыночной стоимости
оборудования. Нужны цена, ссылка, заголовок, регион и дата/время наблюдения.
Есть ли API или партнёрский доступ для такого сценария?
```

Ключевые уточнения:

- разрешён ли мониторинг чужих публичных объявлений;
- есть ли API поиска по товарам/оборудованию;
- можно ли хранить историю цен;
- какие лимиты;
- нужен ли договор или тариф.

### 2. Не Начинать M1-M6 До Ответа

Без подтверждённого источника данных:

- не проектировать миграции;
- не делать UI;
- не делать scheduler;
- не делать дашборды.

### 3. Если Avito Подтвердит API

Следующее решение:

- проектировать источник как `AvitoApiClient`;
- отказаться от HTML-парсинга;
- уточнить лимиты и структуру ответа;
- обновить ТЗ и handoff.

### 4. Если API Нет, Но Парсинг Допустим

Следующий spike должен быть отдельным согласованным исследованием:

- не обходить CAPTCHA;
- не использовать прокси для обхода запретов;
- проверить доступ с разрешённой сетевой среды;
- проверить 5-10 позиций;
- зафиксировать стабильность HTML;
- отдельно принять риск headless browser, если простой HTML недоступен.

### 5. Если Ни API, Ни Парсинг Не Допустимы

Модуль в текущем виде не начинать. Возможные альтернативы:

- другой источник данных;
- платный агрегатор рыночных объявлений;
- ручной импорт как отдельный аналитический инструмент;
- партнёрская выгрузка.

## 11. Финальный Вывод

На 2026-06-17 Avito как источник данных для мониторинга цен не подтверждён.

Публичный API, найденный в каталоге разработчика, не закрывает сценарий поиска рыночных объявлений по товарам/оборудованию. Простой HTML-парсинг с текущего сервера технически не прошёл из-за `HTTP 429` и CAPTCHA.

Рекомендуемое состояние проекта: `hold` до ответа Avito или отдельного решения о допустимом parsing-подходе.
