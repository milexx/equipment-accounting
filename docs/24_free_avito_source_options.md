# Бесплатные И Self-Hosted Варианты Источника Данных Avito

Дата: 2026-06-17.

Статус: `source_not_confirmed`.

Бизнес-ограничение: платные внешние сервисы не подходят. Apify, Bright Data, MarketParser, ShopAPIS и аналогичные paid providers не рассматриваются как production-источник.

Связанные документы:

- `docs/19_avito_data_source_discovery_results.md`;
- `docs/20_intermediary_avito_data_services.md`;
- `docs/23_apify_avito_spike_results.md`.

## 1. Текущее Положение

Официальный публичный API Avito для поиска объявлений по рынку не найден.

Прямой запрос с сервера к Avito search получил:

```text
HTTP 429
CAPTCHA / access restricted
```

Apify технически показал, что структурированные данные получить можно, но это платный внешний сервис. Поэтому Apify получает статус:

```text
no_go_paid_service
```

## 2. Что Остаётся Без Платного Источника

Реалистичные варианты:

1. Полуавтоматический импорт данных.
2. Self-hosted parser research.
3. Сбор по вручную подготовленным URL.
4. Использование браузерной сессии оператора.
5. Альтернативные бесплатные источники цен не из Avito.

Ни один из этих вариантов пока не подтверждён как стабильный production-источник.

## 3. Вариант A: Ручной CSV/Excel Импорт

Суть:

- оценщик вручную собирает объявления;
- сохраняет таблицу с `title`, `price`, `url`, `region`, `date`;
- система импортирует таблицу и строит историю/графики.

Плюсы:

- бесплатно;
- легально и понятно с точки зрения эксплуатации;
- можно быстро сделать без борьбы с CAPTCHA;
- сразу даёт пользу как хранилище истории и отчётов.

Минусы:

- нет автоматического daily monitoring;
- качество зависит от дисциплины пользователя;
- ручной труд остаётся.

Статус:

```text
viable_manual_fallback
```

Это не решает исходную цель полностью, но может быть промежуточным вариантом.

## 4. Вариант B: Self-Hosted Parser Research

Суть:

- писать собственный parser;
- запускать его с нашего сервера или отдельной машины;
- пытаться получать search/result pages Avito без платных посредников.

Проблемы:

- прямой запрос уже получил `HTTP 429`;
- Avito использует защиту, CAPTCHA и rate limits;
- robots.txt ограничивает поисковые URL;
- структура выдачи может меняться;
- поддержка parser станет отдельной постоянной задачей;
- без прокси/браузерного отпечатка/сессий стабильность сомнительна.

Плюсы:

- нет оплаты внешнего сервиса;
- полный контроль над кодом;
- можно ограничить частоту и объём.

Минусы:

- высокий технический риск;
- высокий риск нестабильности;
- вопрос compliance остаётся;
- может потребовать инфраструктуру, которая по факту заменит платный сервис.

Статус:

```text
high_risk_research_only
```

Этот вариант нельзя считать готовым решением без отдельного proof-of-concept.

## 5. Вариант C: Сбор По Вручную Подготовленным URL

Суть:

- пользователь в браузере открывает Avito;
- настраивает регион, категорию, запрос и фильтры;
- копирует готовый URL поиска;
- система пытается периодически обращаться именно к этому URL.

Почему это может быть лучше обычного query:

- URL уже содержит категорию и фильтры;
- меньше мусора в выдаче;
- иногда actor/parser может миновать часть redirect logic;
- запрос становится воспроизводимым.

Но:

- прямой серверный запрос всё равно может получить CAPTCHA;
- URL может устареть;
- Avito может персонализировать или защищать выдачу;
- daily automation не гарантирована.

Статус:

```text
candidate_for_self_hosted_poc
```

## 6. Вариант D: Браузерная Сессия Оператора

Суть:

- сбор выполняется не с серверного HTTP client, а через браузерную сессию;
- пользователь авторизован/не авторизован в браузере сам;
- инструмент может быть локальным помощником, который читает открытую страницу или импортирует сохранённый HTML.

Возможные формы:

- локальный script для обработки сохранённой HTML-страницы;
- browser extension;
- bookmarklet;
- ручное сохранение страницы и импорт;
- semi-manual workflow: "открыл Avito -> сохранил HTML -> импортировал".

Плюсы:

- может обходиться без платного API;
- меньше server-side блокировок;
- пользователь контролирует источник страницы;
- можно начать с импорта сохранённого HTML.

Минусы:

- не полностью автоматический daily monitoring;
- возможны ограничения Avito;
- browser extension или локальный helper добавляют поддержку;
- всё равно нужна фильтрация релевантности.

Статус:

```text
viable_semi_automatic_poc
```

## 7. Вариант E: Альтернативные Бесплатные Источники

Суть:

- искать цены не только на Avito;
- использовать открытые сайты, каталоги, архивы, прайс-листы, поисковую выдачу.

Проблема:

- для вторичного рынка оборудования Avito остаётся ключевым источником;
- поисковые API вроде Exa/SERP не дают полной структурированной выборки;
- цены из магазинов нового оборудования не равны вторичному рынку.

Статус:

```text
useful_for_context_not_primary
```

## 8. Рекомендация

Если платные сервисы исключены, честный следующий путь:

1. Не строить полноценный автоматический daily monitoring прямо сейчас.
2. Сделать короткий self-hosted POC на 1-2 дня:
   - вариант C: готовые URL поиска;
   - вариант D: импорт сохранённого HTML из браузера.
3. Проверить, можно ли стабильно получить хотя бы 20-50 объявлений по 3 позициям.
4. Если POC не проходит, зафиксировать, что полностью автоматический бесплатный Avito monitoring технически не подтверждён.
5. В качестве полезного MVP будущего оценщика рассматривать ручной/полуавтоматический импорт и историю цен.

## 9. Go/No-Go Для Бесплатного Источника

Go, если:

- данные можно получать без платного сервиса;
- цена, URL и title извлекаются стабильно;
- не требуется ежедневное ручное исправление parser;
- есть понятный путь обхода CAPTCHA без нарушения эксплуатационных ограничений;
- можно ограничить нагрузку на Avito;
- результат можно воспроизвести на 3-5 позициях.

No-Go, если:

- каждый запуск упирается в CAPTCHA;
- требуется платная proxy-инфраструктура;
- parser работает только вручную и нестабильно;
- Avito отдаёт разные структуры без предсказуемости;
- качество данных невозможно контролировать.

## 10. Следующий Шаг

Подготовить POC без платных сервисов:

1. Пользователь вручную открывает Avito в браузере по 2-3 позициям.
2. Сохраняет HTML страниц поиска.
3. Мы проверяем, можно ли извлечь из сохранённого HTML:
   - title;
   - price;
   - url;
   - location;
   - date, если есть.
4. Если HTML содержит нужные данные, можно проектировать semi-manual importer.
5. Если HTML не содержит данных или всё грузится динамически, следующий вариант - browser extension/bookmarklet или отказ от бесплатной автоматизации.
