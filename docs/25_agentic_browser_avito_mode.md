# Агентский Браузерный Режим Для Avito

Дата: 2026-06-17.

Статус: `research_candidate_with_limits`.

Цель: исследовать возможность полностью автоматического или агентского режима сбора цен Avito без платных посредников.

Связанные документы:

- `docs/19_avito_data_source_discovery_results.md`;
- `docs/23_apify_avito_spike_results.md`;
- `docs/24_free_avito_source_options.md`.

## 1. Важная Граница

Формулировка "прикинуться пользователем" технически может означать разные вещи.

Допустимый для исследования вариант:

```text
Агент управляет реальным браузером/профилем оператора, открывает страницы, читает видимые объявления и сохраняет структурированные данные.
```

Недопустимый или неприемлемый как архитектурная основа вариант:

```text
Обходить CAPTCHA, скрывать автоматизацию, подбирать fingerprint, использовать stealth/proxy-цепочки и имитировать человека ради обхода антибот-защиты.
```

В проекте нужно рассматривать первый вариант. Если Avito показывает CAPTCHA или "Доступ ограничен", агент должен останавливаться и требовать ручного действия, а не обходить защиту.

## 2. Техническая Идея

Вместо серверного `requests`/`curl` использовать браузерный агент:

```text
Scheduler
  -> Browser Agent
    -> Chrome/Chromium profile
      -> Avito search pages
        -> DOM/embedded JSON extraction
          -> Relevance filter
            -> Daily price snapshot
```

Браузерный агент может:

- открыть сохранённый URL поиска;
- дождаться загрузки страницы;
- прокрутить выдачу;
- извлечь карточки объявлений из DOM или embedded JSON;
- сохранить `title`, `price`, `url`, `location`, `postedDate`;
- зафиксировать screenshot/HAR/HTML для аудита;
- остановиться при CAPTCHA или блокировке.

## 3. Возможные Технологии

### 3.1 Playwright Persistent Context

Playwright поддерживает запуск persistent browser context с отдельным `userDataDir`. В этом каталоге хранятся cookies и localStorage.

Практический смысл:

- заводится отдельный профиль только для оценщика;
- оператор один раз вручную открывает браузер и проходит штатные проверки;
- агент дальше использует этот профиль для чтения публичных страниц;
- основной пользовательский Chrome-профиль не трогаем.

Ограничение: Playwright документация предупреждает, что автоматизировать основной профиль Chrome не следует. Нужно использовать отдельный automation profile.

### 3.2 Подключение К Существующему Браузеру По CDP

Playwright умеет подключаться к Chromium-based browser через Chrome DevTools Protocol.

Практический смысл:

- можно запустить отдельный Chrome с remote debugging;
- оператор видит окно браузера;
- агент подключается к уже открытому браузеру и выполняет действия.

Ограничения:

- ниже надёжность по сравнению с обычным Playwright protocol;
- remote debugging нельзя открывать наружу;
- это повышает риск безопасности, если профиль содержит лишние cookies.

### 3.3 Browser Extension / Bookmarklet

Расширение браузера или bookmarklet может читать открытую страницу Avito и передавать карточки в локальный сервис.

Практический смысл:

- оператор сам открывает нужную страницу;
- расширение извлекает данные с текущей страницы;
- можно избежать server-side блокировки;
- не требуется платный provider.

Минус: это уже не полностью автоматический daily monitoring, а semi-automatic режим.

## 4. Что Можно Автоматизировать

Можно автоматизировать:

- открытие заранее сохранённых URL поиска;
- ожидание загрузки;
- скролл страницы;
- извлечение карточек;
- сохранение HTML/screenshot для аудита;
- распознавание состояния `captcha/access restricted/no results`;
- повтор с низкой частотой;
- запуск по расписанию, если сайт не требует ручного действия.

Нельзя закладывать в архитектуру:

- автоматическое решение CAPTCHA;
- обход блокировок;
- массовую ротацию fingerprints;
- прокси-фермы;
- маскировку под разных пользователей;
- действия, которые требуют нарушения условий площадки.

## 5. Риски

### 5.1 Надёжность

Даже настоящий браузер может получить CAPTCHA или ограничение доступа. Для production это означает:

- daily job может часто переходить в статус `needs_human`;
- данные будут неполными;
- нужен экран контроля ошибок.

### 5.2 Качество Данных

Apify spike показал, что главная проблема не только доступ к Avito, но и релевантность:

- расходники;
- запчасти;
- аксессуары;
- похожие модели;
- объявления "на запчасти";
- слишком дешёвые и нерелевантные позиции.

Поэтому агентский браузерный режим всё равно требует `ListingRelevanceFilter`.

### 5.3 Безопасность

Браузерный агент работает с правами пользователя браузера. Поэтому:

- использовать только отдельный профиль;
- не хранить в нём почту, банки, админки и другие сайты;
- не давать агенту произвольные задачи;
- ограничить домены `avito.ru`;
- сохранять журнал действий;
- не разрешать отправку форм, сообщений, покупок и изменение аккаунта.

### 5.4 Compliance

Avito ограничивает автоматический сбор и защищает выдачу. Поэтому агентский режим должен быть оформлен как исследовательский риск:

- минимальная частота;
- малый объём;
- чтение публичных карточек;
- остановка при CAPTCHA;
- отсутствие сбора телефонов и персональных данных;
- отсутствие попыток обхода блокировок.

## 6. Архитектура POC

POC без записи в основную БД:

```text
configs/avito_search_urls.json
  -> browser_agent_run
    -> /tmp/avito-agent-runs/{run_id}/raw.html
    -> /tmp/avito-agent-runs/{run_id}/screenshot.png
    -> /tmp/avito-agent-runs/{run_id}/listings.json
    -> /tmp/avito-agent-runs/{run_id}/run_report.json
```

В `run_report.json`:

```json
{
  "status": "success|needs_human|blocked|no_results|parser_error",
  "query_code": "kyocera_m2040dn",
  "url": "https://www.avito.ru/...",
  "started_at": "datetime",
  "finished_at": "datetime",
  "items_found": 0,
  "items_with_price": 0,
  "captcha_detected": false,
  "access_restricted_detected": false,
  "notes": []
}
```

## 7. POC Сценарий

1. Создать отдельный browser profile:

```text
/opt/workspace/projects/equipment-accounting/var/avito-browser-profile
```

2. Оператор вручную открывает браузер с этим профилем.
3. Оператор открывает Avito и подтверждает, что страница поиска работает.
4. Сохраняем 3 готовых URL поиска:
   - `Kyocera ECOSYS M2040dn`;
   - `Lenovo ThinkPad T14`;
   - `Dell PowerEdge R740`.
5. Агент запускает браузер в headed mode, открывает URL и извлекает карточки.
6. Если появляется CAPTCHA или блокировка, агент фиксирует `needs_human` и останавливается.
7. Сравниваем результат с Apify spike:
   - есть ли `title`;
   - есть ли `price`;
   - есть ли `url`;
   - есть ли `location`;
   - сколько шума.

## 8. Go/No-Go

Go для дальнейшего prototype:

- 3 URL открываются без CAPTCHA при низкой частоте;
- агент получает хотя бы 20 карточек по массовым позициям;
- `title`, `price`, `url` извлекаются стабильно;
- повторный запуск через несколько часов даёт сопоставимый результат;
- CAPTCHA корректно переводит job в `needs_human`, а не ломает процесс;
- браузерный профиль изолирован.

No-Go:

- Avito стабильно показывает CAPTCHA даже в headed browser;
- данные карточек не доступны в DOM/HTML;
- нужна платная proxy/fingerprint инфраструктура;
- нужны обходы защиты;
- результат нестабилен и требует ежедневного ручного ремонта.

## 9. Вывод

Полностью автоматический бесплатный режим через Avito возможен только как research hypothesis.

Самый корректный технический вариант:

```text
Agentic browser with isolated user profile, low frequency, no CAPTCHA bypass, stop-on-block.
```

Это не гарантирует production-работоспособность, но это единственный оставшийся путь к автоматизации без платных сервисов и без написания прямого HTTP parser, который уже упирается в `429/CAPTCHA`.

Следующий шаг: сделать локальный POC browser-agent на 3 готовых Avito search URL и проверить, открываются ли страницы в headed browser с отдельным профилем.
