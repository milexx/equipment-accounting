# Разработка, Демо И Релизы

## 1. Принцип

Разработка ведётся в этом проекте:

```text
/opt/workspace/projects/equipment-accounting
```

Здесь же поднимается демо всего нового: интерфейс, сценарии, тестовые данные и прототипы.

Промышленная среда отдельно. В неё ничего не копируется вручную из рабочей папки. Релиз в промышленную среду должен идти из зафиксированной версии в git.

## 2. Git

Проект должен быть отдельным git-репозиторием.

Рекомендуемые ветки:

- `main` - стабильная ветка, только проверенные изменения;
- `dev` - текущая разработка и демо;
- `feature/*` - отдельные крупные задачи;
- `release/*` - подготовка релиза в промышленную среду;
- `hotfix/*` - срочные исправления промышленной версии.

Минимальный процесс:

```text
feature/* -> dev -> main -> release tag -> production
```

Для маленького проекта на старте допустимо работать в `main`, но перед промышленным запуском нужно перейти на процесс с `dev` и релизными тегами.

## 3. Демо-Среда

Демо запускается из текущего проекта.

Назначение демо:

- показать новые экраны;
- проверить сценарии региона;
- проверить сценарии центра;
- протестировать фильтры, фото, статусы, оценку и продажу;
- собрать обратную связь до промышленного релиза.

Демо может использовать:

- локальную БД;
- тестовые регионы;
- тестовых пользователей;
- тестовые фото;
- синтетические записи оборудования.

Демо не должно использовать реальные промышленные секреты и доступы.

## 4. Промышленный Релиз

Промышленный релиз выпускается только из git.

Перед релизом:

- все изменения закоммичены;
- миграции Alembic готовы;
- тесты пройдены;
- есть release notes;
- есть backup-план;
- проверено, что `.env` и секреты не попали в репозиторий;
- версия помечена git tag.

Формат тега:

```text
v0.1.0
v0.2.0
v1.0.0
```

## 5. Что Не Хранить В Git

Не хранить:

- `.env`;
- пароли;
- токены;
- реальные персональные данные;
- реальные фото оборудования, если они чувствительные;
- runtime exports;
- локальную БД;
- временные файлы.

Хранить:

- код;
- миграции;
- документацию;
- шаблоны конфигурации;
- тестовые seed-данные без секретов;
- прототипы;
- инструкции запуска.

## 6. Следующие Технические Шаги

После инициализации git:

1. Сделать первый commit с документацией и прототипом.
2. Добавить scaffold FastAPI-приложения.
3. Добавить `.env.example`.
4. Добавить `README` с запуском демо.
5. Добавить seed-данные для демо.
6. Настроить простую команду запуска демо.
