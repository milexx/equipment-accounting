# Исследование Промежуточных Сервисов Для Данных Avito

Дата исследования: 2026-06-17.

Цель: проверить, можно ли использовать промежуточные сервисы вместо прямого парсинга Avito с нашего сервера.

Связанные документы:

- `docs/18_avito_data_source_discovery.md`;
- `docs/19_avito_data_source_discovery_results.md`.

## 1. Итоговое Решение

Текущий статус: `hold_vendor_shortlist`.

Прямой официальный API Avito для поиска публичных объявлений по товарам/оборудованию не найден. Прямой HTML-запрос с нашего сервера получил `HTTP 429` и CAPTCHA.

Промежуточные сервисы технически могут закрыть задачу, но их нужно разделить на категории:

1. Search API / AI search: Exa, SERP API.
2. Scraping platform / hosted actors: Apify.
3. Enterprise scraping infrastructure: Bright Data.
4. Специализированные сервисы мониторинга Avito: MarketParser, Smart Price For Avito, ShopAPIS.

Для целевого модуля мониторинга цен наиболее реалистичны:

- специализированный сервис мониторинга Avito;
- hosted scraper/API с явным Avito support;
- enterprise scraping provider с договором и SLA.

Exa полезен для discovery и ручной проверки, но не является надёжным источником ежедневного ценового среза.

## 2. Критерии Оценки

Промежуточный сервис подходит, если он:

- возвращает структурированные объявления;
- возвращает цену числом;
- возвращает ссылку на объявление;
- возвращает заголовок;
- возвращает регион/город;
- поддерживает текстовый запрос;
- поддерживает регион Avito;
- поддерживает лимит 50-100 объявлений на позицию;
- допускает ежедневный запуск по расписанию;
- имеет API или регулярную выгрузку;
- имеет понятную legal/compliance позицию;
- не требует от нас обходить CAPTCHA, блокировки и rate limits.

Сервис не подходит как основной источник, если он:

- возвращает только поисковые сниппеты;
- не гарантирует полноту выдачи;
- не даёт цену как структурированное поле;
- не даёт управлять регионом Avito;
- не имеет понятных условий использования;
- завязан на контактные данные продавцов как основную ценность.

## 3. Exa

### Что Это

Exa - web search API для поиска web-страниц и извлечения содержимого из результатов. В документации описан endpoint `/search`, который возвращает список найденных URL и может возвращать text/highlights/summary.

### Проверка На Тестовых Запросах

Проверены запросы:

```text
site:avito.ru Kyocera ECOSYS M2040dn цена объявление
site:avito.ru Dell PowerEdge R740 цена объявление
site:avito.ru Lenovo ThinkPad T14 цена объявление
```

Результат:

- Exa находит отдельные Avito-страницы;
- по некоторым страницам в highlights видны цены;
- иногда находятся страницы категорий/поиска с несколькими объявлениями и ценами;
- часть результатов содержит только общий текст Avito без цены;
- встречаются снятые объявления;
- полнота и актуальность выдачи не контролируются;
- нет гарантии, что будут получены первые 50-100 актуальных объявлений по Avito-фильтру.

### Оценка

Exa не подходит как основной источник мониторинга цен.

Причины:

- это search/retrieval API, а не Avito listing API;
- результат зависит от индекса и ранжирования Exa;
- нельзя гарантировать ежедневную полноту выборки;
- цена не является гарантированным структурированным полем;
- регион Avito не управляется как нативный фильтр;
- невозможно надёжно отличить актуальное активное объявление от старого/снятого;
- min/max/median по Exa-результатам будут методологически слабыми.

Допустимое применение:

- discovery источников;
- ручная проверка наличия объявлений;
- обогащение ссылки текстом, если URL уже известен;
- fallback для аналитика, но не автоматический расчёт цены.

Решение: Exa не брать как источник daily snapshots.

## 4. SERP API

### Что Это

SERP API, например Bright Data SERP API, возвращает результаты поисковых систем: Google, Bing, DuckDuckGo, Yandex и другие. Это не прямой Avito API.

### Оценка

SERP API не подходит как основной источник цен Avito.

Причины:

- поисковик индексирует не все объявления;
- выдача зависит от SEO, индекса, персонализации и свежести;
- цена часто находится только в сниппете или не находится вообще;
- невозможно гарантировать 50-100 актуальных объявлений за день;
- регион Avito не совпадает с регионом поисковой системы;
- невозможно корректно считать дневной min/max/median рынка.

Допустимое применение:

- найти релевантные Avito URL для ручной проверки;
- мониторить видимость объявления в поисковиках;
- вспомогательный discovery.

Решение: SERP API не брать как источник daily snapshots.

## 5. Apify Actors

### Что Найдено

В Apify Marketplace есть несколько Avito actors:

- `server0/avito-scraper`;
- `abotapi/avito-ru-scraper`;
- `ahaham_bytiz/avito-scraper`;
- `zen-studio/avito-listings-scraper`;
- другие community actors.

### Пример Возможностей

Actor `server0/avito-scraper` заявляет:

- поиск по keyword;
- регион как slug Avito, например `rossiya`, `moskva`, `sankt-peterburg`;
- категория как slug;
- priceMin/priceMax;
- maxItems;
- сортировка;
- structured output: id, title, price, currency, url, location, category, postedDate, photoCount, sellerRating;
- использование embedded catalog JSON Avito;
- API-запуск через Apify;
- необходимость Russian residential proxies.

В документации actor прямо указано, что без хорошего российского IP pool Avito чаще всего отдаёт "Доступ ограничен".

### Оценка

Apify технически ближе всего к нашему сценарию, потому что уже есть actors, которые возвращают структурированные объявления.

Плюсы:

- есть готовые Avito-specific integrations;
- есть API запуска;
- можно получать dataset items;
- есть поля, нужные для дневных срезов;
- можно ограничивать maxItems;
- можно тестировать без разработки собственного парсера;
- можно заменить actor, не меняя нашу доменную модель, если сделать адаптер `ExternalAvitoProvider`.

Минусы:

- многие actors community-made, а не официальный Avito endpoint;
- качество и поддержка зависят от автора actor;
- часть actors прямо использует residential proxies и anti-blocking;
- legal/compliance остаётся на пользователе;
- риск внезапной поломки остаётся;
- нужно оплачивать Apify + actor usage + proxy usage;
- требуется отдельный pilot-run на наших позициях.

Решение: Apify можно рассматривать как кандидат для M0.1 vendor spike, но не принимать без теста и compliance-review.

## 6. Bright Data

### Что Найдено

Bright Data предлагает:

- Avito Scraper;
- AI Scraper Studio;
- API delivery;
- scheduled scraping;
- JSON/NDJSON/CSV/Parquet;
- встроенные proxies, unblocking, CAPTCHA logic, JavaScript rendering;
- pricing от page loads;
- enterprise support и SLA.

Bright Data SERP API отдельно не является прямым решением для Avito, но Bright Data Avito Scraper/Web Scraper - потенциально релевантен.

### Оценка

Bright Data - кандидат enterprise-класса.

Плюсы:

- инфраструктура против блокировок и CAPTCHA на стороне поставщика;
- delivery через API/webhook/storage;
- можно формализовать SLA;
- больше шансов на поддержку при изменениях Avito;
- подходит для промышленного vendor-варианта.

Минусы:

- это всё равно scraping-подход, не официальный Avito API;
- legal/compliance надо проверять договором;
- стоимость может быть выше;
- нужна настройка конкретного extraction schema;
- нужно пилотировать на российских Avito-запросах.

Решение: Bright Data подходит для vendor shortlist, особенно если бизнес готов к договору с поставщиком данных.

## 7. MarketParser

### Что Найдено

MarketParser предлагает "Мониторинг Авито":

- поисковые запросы или ссылки на объявления;
- регионы;
- расписание;
- ручной запуск;
- сбор названия, цены, продавца;
- регион и категория;
- дата размещения и обновления;
- статус объявления;
- история;
- XLSX/CSV;
- JSON API;
- личный кабинет.

Ценообразование описано через "проверки": одно сканирование цены одного товара на одной площадке в одном регионе. Указаны тарифы от 100 000 проверок в месяц.

### Оценка

MarketParser очень близок к бизнес-сценарию.

Плюсы:

- уже позиционируется как мониторинг цен Avito;
- поддерживает расписание и историю;
- есть JSON API;
- есть CSV/XLSX;
- есть регионы;
- можно использовать как внешний источник без разработки парсера;
- российский контекст и понятная бизнес-модель.

Минусы:

- нужно проверить API на практике;
- нужно проверить, можно ли отдавать именно по 100-200 позициям оборудования;
- нужно проверить SLA, договор, хранение данных;
- возможно, сервис больше ориентирован на retail/конкурентный мониторинг, а не б/у оборудование.

Решение: MarketParser - один из лучших кандидатов для коммерческого pilot.

## 8. Smart Price For Avito

### Что Найдено

SPFA заявляет:

- анализ позиций и цен Avito;
- рекомендации по цене для выхода в топ;
- API;
- Excel;
- получение телефонов продавцов по ID объявлений;
- проверка первой страницы выдачи;
- фокус на новое товарное предложение.

### Оценка

SPFA потенциально полезен, но требует осторожности.

Плюсы:

- Avito-specific;
- есть API;
- есть ценовые рекомендации;
- может быть полезен для оценки позиции собственного объявления.

Минусы:

- фокус не полностью совпадает: сервис ориентирован на позицию в выдаче и стратегию цены, а не на независимый сбор 50-100 объявлений по любым б/у позициям;
- получение телефонов продавцов не нужно нашему модулю и повышает privacy/compliance риск;
- нужно проверить, отдаёт ли API список объявлений и цены, а не только рекомендации по одному объявлению;
- заявлена проверка первой страницы, что может быть недостаточно.

Решение: рассматривать только после уточнения API. Не первый кандидат.

## 9. ShopAPIS

### Что Найдено

ShopAPIS описывает Avito product data API:

- asking price в RUB;
- condition new/used;
- seller type;
- location;
- description;
- category;
- photos;
- listing ID;
- listing URL;
- posted/refreshed date;
- fetched_at;
- use case: used-goods price benchmarking.

Также прямо указано, что официальный Avito seller API ограничен и не возвращает open marketplace конкурентов.

### Оценка

ShopAPIS выглядит концептуально близко к нашему сценарию.

Плюсы:

- структурированный Avito listing data;
- фокус на used-goods pricing;
- нормализация condition/seller/location;
- API-ориентированный подход;
- формулировка use case совпадает с нашим мониторингом.

Минусы:

- нужно проверить покрытие России и нужных категорий;
- нужно запросить pricing, SLA и юридические условия;
- нужно проверить, умеет ли он искать по произвольным моделям оборудования, а не только отдавать данные по известным listing URLs;
- нужна pilot-интеграция.

Решение: добавить в shortlist рядом с MarketParser и Bright Data.

## 11. Рекомендованный Следующий Шаг

Не начинать разработку собственного парсера.

Сначала провести vendor spike по 3 кандидатам:

1. MarketParser.
2. ShopAPIS.
3. Apify actor `server0/avito-scraper` или более зрелый paid actor.

Bright Data оставить как enterprise option, если нужен договор/SLA и бюджет выше.

### Что Запросить У Вендора

Для каждого кандидата:

- можно ли искать по произвольному текстовому запросу;
- можно ли указать регион Avito;
- можно ли получить 50-100 объявлений по запросу;
- какие поля возвращаются;
- есть ли цена числом;
- есть ли ссылка;
- есть ли дата публикации/обновления;
- есть ли статус активности объявления;
- есть ли API;
- можно ли запускать ежедневно по расписанию;
- есть ли история на стороне сервиса;
- можно ли хранить данные у нас;
- условия legal/compliance;
- SLA и поддержка при изменениях Avito;
- стоимость для 100-200 позиций в день.

### Pilot Dataset

Проверить 5 позиций:

```text
Kyocera ECOSYS M2040dn
HP LaserJet Pro MFP M426
Lenovo ThinkPad T14
Dell PowerEdge R740
Dell P2419H
```

Для каждой:

- регион `rossiya`;
- max 50 объявлений;
- ежедневный или ручной test run;
- выгрузка JSON/CSV;
- проверка price/url/title/location/date.

## 12. Архитектурное Последствие

В архитектуре модуля источник должен быть не `AvitoParser`, а более общий `PriceDataProvider`.

Рекомендуемый контракт:

```text
PriceDataProvider.fetch_listings(search_query, search_region, limit) -> list[PriceListing]
```

Реализации:

```text
MarketParserProvider
ShopApisProvider
ApifyAvitoProvider
BrightDataAvitoProvider
DirectAvitoParserProvider
```

DirectAvitoParserProvider оставить последним вариантом, а не первым.

## 13. Решение Для Текущего Проекта

Статус Avito source меняется:

```text
hold -> hold_vendor_shortlist
```

Обоснование:

- прямой Avito API не найден;
- прямой requests-парсинг с нашего сервера не прошёл;
- существуют промежуточные сервисы, которые потенциально дают нужные данные;
- прежде чем делать модуль, надо выбрать и проверить одного поставщика данных.

Следующий документ после vendor spike:

```text
docs/21_avito_vendor_spike_results.md
```

В нём нужно зафиксировать выбранного поставщика или решение `no_go`.
