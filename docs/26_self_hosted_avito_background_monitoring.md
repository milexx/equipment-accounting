# Self-Hosted Фоновый Мониторинг Avito

Дата: 2026-06-17.

Статус: `research_candidate_self_hosted_parser`.

Цель: найти путь к полностью автоматическому фоновому мониторингу цен Avito без платного SaaS-поставщика данных.

Связанные документы:

- `docs/19_avito_data_source_discovery_results.md`;
- `docs/24_free_avito_source_options.md`;
- `docs/25_agentic_browser_avito_mode.md`.

## 1. Обновлённый Вывод

После исключения платных сервисов самый реалистичный технический путь:

```text
self-hosted Avito parser
  -> background worker
  -> saved Avito search URLs
  -> local JSON/Excel/SQLite output
  -> relevance filter
  -> daily min/max/median snapshot
```

То есть не писать parser с нуля и не строить сложного browser-agent самостоятельно, а сначала проверить готовый open-source parser, который уже решает часть задач:

- фоновый режим;
- Docker/VPS запуск;
- Playwright/browser mode;
- сохранение результатов;
- уведомления;
- отслеживание новых объявлений;
- частично отслеживание изменения цены.

## 3. Важное Ограничение

Это не официальный Avito API.

Даже готовый parser остаётся scraping-решением и наследует риски:

- блокировки;
- CAPTCHA;
- изменения HTML;
- зависимость от cookies/proxy;
- возможные ограничения Avito terms;
- необходимость сопровождения.

Документация `Duff89/parser_avito` сама описывает способы борьбы с блокировками:

- мобильный прокси;
- сторонний cookies-сервис;
- собственный аккаунт;
- смена cookies/IP.

Это означает: бесплатный production-режим не гарантирован. Но это лучший кандидат для технического POC фонового мониторинга.

## 4. Про "Прикинуться Пользователем"

Технически есть три уровня:

### Уровень 1. Нормальный Browser Mode

Parser использует реальный браузер/Playwright, задержки, cookies и читает публичные страницы.

Статус:

```text
acceptable_for_poc
```

Это можно проверять.

### Уровень 2. Собственный Аккаунт Avito

Parser работает с cookies/сессией отдельного аккаунта, созданного только под мониторинг.

Плюсы:

- может быть дешевле, чем платные сервисы;
- ближе к поведению обычного пользователя;
- может снизить частоту блокировок.

Минусы:

- есть риск блокировки аккаунта;
- нельзя использовать основной рабочий/личный аккаунт;
- нужно изолировать профиль;
- нельзя собирать телефоны, писать продавцам, делать действия от имени аккаунта.

Статус:

```text
possible_but_risky
```

### Уровень 3. Stealth / Anti-captcha / Proxy Rotation

Подмена fingerprints, обход CAPTCHA, массовая ротация IP, покупка cookies.

Статус:

```text
not_a_clean_free_solution
```

Это либо платно, либо юридически/эксплуатационно рискованно. Такой путь не стоит принимать как основную архитектуру.

## 5. Почему Готовый Parser Лучше, Чем Наш С Нуля

Плюсы готового parser:

- уже есть обработка Avito-специфики;
- уже есть фоновый loop;
- уже есть экспорт;
- уже есть память просмотренных объявлений;
- уже есть документация по Docker/VPS;
- можно проверить за часы, а не проектировать неделю;
- можно форкнуть и адаптировать output под наш `PriceDataProvider`.

Минусы:

- внешний open-source код надо аудитить;
- не факт, что лицензия/качество кода подходят;
- нужно отделить полезное ядро от GUI/уведомлений;
- нужно добавить нашу нормализацию и фильтрацию релевантности;
- нужно зафиксировать stop-on-block поведение.

## 6. Архитектура С Использованием Self-Hosted Parser

Не встраивать parser прямо в MVP.

Правильнее сделать отдельный sidecar/process:

```text
equipment-accounting
  app/
  docs/
  ...

avito-monitor-worker
  parser engine
  config search_urls
  local output JSON/SQLite
  logs
```

Интеграция:

```text
Avito parser output
  -> normalized ExternalListing JSON
  -> equipment-accounting import job
  -> ListingRelevanceFilter
  -> DailyPriceSnapshot
```

Так MVP не зависит напрямую от нестабильного parser.

## 7. POC План

POC должен быть отдельным от MVP.

### Шаг 1. Клонировать parser в `/tmp`

Не добавлять его в основной репозиторий.

### Шаг 2. Проверить лицензию и зависимости

Нужно понять:

- лицензия;
- Python version;
- Playwright/браузеры;
- Docker support;
- формат конфигурации;
- формат output.

### Шаг 3. Запустить на 1 URL

Первый URL:

```text
Kyocera ECOSYS M2040dn, вся Россия, категория оргтехника/расходники или максимально близкий фильтр
```

Цель:

- получить хотя бы 10 объявлений;
- сохранить JSON/Excel;
- проверить поля: title, price, url, location, date.

### Шаг 4. Запустить на 3 URL

Позиции:

- `HP LaserJet Pro MFP M426`;
- `Lenovo ThinkPad T14`;
- `Dell PowerEdge R740`.

### Шаг 5. Проверить фоновый режим

Запуск:

```text
один run каждые 30-60 минут
```

Критерии:

- не падает;
- не получает постоянную CAPTCHA;
- не требует ручного UI;
- пишет логи;
- сохраняет новые объявления;
- фиксирует изменение цены, если поддерживается.

## 8. Go/No-Go

Go:

- parser запускается без платного сервиса;
- выдаёт структурированные данные;
- работает минимум несколько циклов подряд;
- блокировки не возникают на низкой частоте;
- можно настроить 10-20 URL;
- output можно адаптировать под наш import;
- не требуется основной пользовательский аккаунт;
- CAPTCHA переводит процесс в `needs_human` или retry, а не ломает данные.

Hold:

- работает только через отдельный аккаунт Avito;
- периодически требует ручной CAPTCHA;
- нужен статический proxy до 120-300 ₽/мес;
- качество данных нормальное, но требуется фильтрация.

No-Go:

- без мобильного proxy/cookies-сервиса не работает;
- блокировки постоянные;
- parser требует платные antiblock-компоненты;
- output нестабильный;
- невозможно отделить parser от GUI;
- невозможно безопасно запустить в фоне.
