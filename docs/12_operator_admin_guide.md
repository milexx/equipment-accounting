# Инструкция Оператора И Администратора

## 1. Роли

В MVP используются три роли:

- `region` - пользователь региона;
- `center` - сотрудник центра;
- `center_admin` - администратор центра.

## 2. Вход

Страница входа:

```text
/login
```

Демо-пользователи:

- `admin` - администрирование;
- `center` - реестр и карточки центра;
- `region24`, `region08`, `region31` - рабочие места регионов.

## 3. Работа Региона

Регион после входа попадает в `/region`.

Основной процесс:

1. Открыть рабочее место региона.
2. Нажать добавление оборудования внутри интерфейса региона.
3. Заполнить тип, наименование, местонахождение, состояние и обязательные поля.
4. Для нерабочего оборудования описать поломку и приложить фото дефекта.
5. Сохранить черновик или отправить карточку в центр.
6. Если центр вернул карточку на доработку, открыть её, исправить данные и повторно отправить.

Регион видит только свои карточки и не может открыть карточки другого региона.

## 4. Работа Центра

Центр после входа попадает в `/equipment`.

Основной процесс:

1. Открыть реестр центра.
2. Использовать очереди и фильтры: регион, тип, местонахождение, статус продажи, динамические поля.
3. Открыть карточку.
4. Проверить данные, фото и историю.
5. Принять карточку или вернуть региону на доработку с комментарием.
6. После принятия выбрать маршрут: диагностика, списание, оценка, продажа.
7. Для продажи заполнить оценку, цену, описание, затем перевести карточку в публикацию или продажу.
8. Для списания согласовать списание, перевести к утилизации и зафиксировать утилизацию.
9. При необходимости архивировать карточку или выполнить soft delete.

Все ключевые изменения карточки пишутся в историю.

## 5. Работа Администратора

Администратор после входа пользователем `admin` попадает в `/admin`.

В admin-разделе можно:

- создавать и редактировать пользователей;
- назначать роли `region`, `center`, `center_admin`;
- привязывать регионального пользователя к региону;
- включать и отключать пользователей;
- создавать и редактировать регионы;
- включать и отключать регионы;
- создавать и редактировать типы оборудования;
- создавать и редактировать поля типов;
- настраивать обязательность, порядок, фильтруемость и варианты значений полей.

Отключение типа или поля не удаляет исторические данные.

## 6. Экспорт

CSV-экспорт доступен из реестра центра.

Экспорт учитывает текущие фильтры и ограничен 10 000 строками.

## 7. Приёмочная Проверка

Перед проверкой должен быть запущен dev-сервер:

```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8010
```

Команда приёмки:

```bash
.venv/bin/python -c "from scripts.check_mvp_acceptance import main; raise SystemExit(main())"
```

Проверка проходит:

- smoke-тест основных страниц;
- проверку доступов;
- защиту от двойной отправки;
- конфликт `row_version`;
- загрузку и удаление фото;
- создание 60 параллельных карточек;
- работу центра со списком во время массового создания.
