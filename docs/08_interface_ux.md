# Интерфейс И UX

Цель интерфейса - дать регионам быстрый ввод без обучения, а центру - управляемую работу с большим объёмом данных.

## 1. Выводы Из Анализа Похожих Систем

В asset management системах повторяются полезные паттерны:

- кастомные поля группируются в наборы и показываются только для выбранного типа оборудования;
- важные поля можно выводить колонками в общем списке;
- список должен поддерживать сохранённые представления: выбранные колонки, фильтры, сортировка;
- для большого реестра нужны массовые действия;
- фото/изображения помогают быстро узнавать актив;
- barcode/QR-поиск и asset tag сокращают ручной ввод;
- статус и жизненный цикл должны быть видны прямо в списке;
- в карточке нужна история изменений.

Для нашего проекта это означает:

- региону нельзя показывать сложный административный интерфейс;
- форма добавления должна вести пользователя по шагам;
- выбор состояния должен быть простым и понятным;
- если оборудование нерабочее, интерфейс должен сразу просить описание поломки и фото дефекта;
- центр должен работать через таблицу, фильтры, сохранённые виды и массовые операции;
- центр должен видеть очереди по дальнейшей судьбе: диагностика, списание, утилизация, оценка, продажа;
- динамические поля должны быть видны в форме и таблице только тогда, когда они нужны.

## 2. Принципы

### Для Регионов

- Минимум полей на первом экране.
- Один главный сценарий: добавить оборудование.
- Форма разделена на короткие смысловые блоки.
- Поля появляются после выбора типа оборудования.
- Система сразу показывает, что осталось заполнить.
- Фото добавляются простым drag-and-drop или кнопкой выбора.
- Черновик сохраняется автоматически или явной кнопкой.
- Ошибки показываются рядом с полем, а не общим текстом сверху.
- После сохранения пользователь получает понятный следующий шаг: добавить ещё, открыть карточку, отправить на проверку.

### Для Центра

- Главный экран - реестр, не dashboard.
- Таблица плотная, но читаемая.
- Быстрые фильтры всегда видны.
- Расширенные фильтры открываются по необходимости.
- Колонки можно настраивать и сохранять как представления.
- Сохранённые представления доступны в один клик.
- Есть массовые действия: принять, вернуть, архивировать, экспортировать.
- Статусы и проблемные записи визуально заметны.
- Карточка оборудования открывается без потери контекста списка.

## 3. Региональный Интерфейс

### Главная Страница Региона

Назначение: быстро понять текущие задачи и добавить оборудование.

Блоки:

- кнопка `Добавить оборудование`;
- счётчики: черновики, отправлено, на доработке, принято;
- список последних записей региона;
- блок записей, требующих доработки.

Не показывать:

- глобальную аналитику;
- администрирование типов;
- сложные фильтры центра.

### Форма Добавления

Форма должна быть похожа на короткий мастер:

1. Тип оборудования.
2. Основные сведения.
3. Состояние.
4. Поля выбранного типа.
5. Фото.
6. Проверка и отправка.

Правила:

- пока тип не выбран, динамические поля не показываются;
- обязательные поля помечаются явно;
- инвентарный и серийный номер доступны сразу;
- состояние выбирается одной простой группой: рабочее, нерабочее, нужна диагностика;
- при выборе `нерабочее` появляются поля `Что сломано` и подсказка добавить фото поломки;
- фото-блок показывает счётчик `1 из 5 минимум`;
- для нерабочего оборудования фото-блок показывает счётчик `Фото дефекта: минимум 1`;
- кнопка `Отправить на проверку` недоступна, пока не выполнены обязательные условия;
- кнопка `Сохранить черновик` доступна всегда после минимального ввода.

### Быстрый Ввод

Для снижения нагрузки на регионы:

- после успешного добавления показывать кнопку `Добавить ещё такой же тип`;
- запоминать последний выбранный тип;
- поддержать копирование предыдущей записи как черновика;
- разрешить загрузить несколько фото сразу;
- позже добавить QR/штрихкод-сканирование через камеру или внешний сканер.

## 4. Центральный Интерфейс

### Реестр Оборудования

Главный экран центра.

Обязательные элементы:

- строка поиска;
- быстрые фильтры: регион, тип, статус;
- кнопка расширенных фильтров;
- переключатель сохранённых представлений;
- настройка колонок;
- экспорт;
- массовые действия;
- таблица с пагинацией.

Базовые колонки:

- чекбокс выбора;
- фото-превью;
- статус;
- регион;
- тип;
- наименование;
- инвентарный номер;
- серийный номер;
- обновлено;
- ответственный/автор;
- действия.

### Сохранённые Представления

Представление хранит:

- фильтры;
- набор колонок;
- порядок колонок;
- сортировку;
- размер страницы;
- признак “по умолчанию”.

Примеры представлений:

- `Новые на проверку`;
- `Требуют доработки`;
- `Требуют диагностики`;
- `К списанию`;
- `К утилизации`;
- `На оценку`;
- `Готово к продаже`;
- `Опубликовано`;
- `Продано`;
- `Серверы`;
- `Без серийного номера`;
- `Архив`.

### Массовые Действия

Для выбранных записей:

- принять;
- отправить на диагностику;
- отправить на списание;
- отправить на оценку;
- подготовить к продаже;
- вернуть на доработку;
- архивировать;
- экспортировать;
- сменить тип, если разрешено;
- назначить комментарий центра.

Массовые действия должны требовать подтверждения.

## 5. Карточка Оборудования

Карточка должна показывать:

- фото-галерею;
- статус и действия по статусу;
- состояние оборудования;
- описание поломки, если оборудование нерабочее;
- оценку и цену продажи, если оборудование рабочее и готовится к продаже;
- базовые поля;
- динамические поля;
- комментарий региона;
- комментарий центра;
- историю изменений;
- техническую информацию: ID, даты, авторы.

Для центра карточка должна иметь действия:

- принять;
- классифицировать как рабочее/нерабочее/требует диагностики;
- отправить на списание;
- отправить на утилизацию;
- отправить на оценку;
- подготовить к продаже;
- вернуть на доработку;
- редактировать;
- архивировать.

Для региона:

- редактировать, если статус позволяет;
- отправить на проверку;
- посмотреть замечания.

## 6. Администрирование Типов

Экран управления типами должен быть понятным для центра:

- список типов;
- количество записей по типу;
- активность;
- кнопка `Поля`;
- кнопка `Создать тип`.

Экран полей типа:

- таблица полей;
- drag-and-drop или кнопки вверх/вниз для порядка;
- тип поля;
- обязательность;
- фильтруемость;
- активность;
- предпросмотр формы для региона.

## 6.1. Будущий Магазин

Магазин не входит в первый MVP, но интерфейс центра должен готовить данные для него.

Для оборудования, готового к продаже, центр заполняет:

- описание для витрины;
- цену продажи;
- состояние;
- комплектность;
- главное фото;
- признак публикации.

Будущая витрина должна показывать только записи со статусом `listed_for_sale` и скрывать служебные поля центра.

## 7. Ошибки И Подсказки

Ошибки:

- рядом с конкретным полем;
- коротким человеческим текстом;
- с подсказкой, как исправить.

Примеры:

- `Добавьте хотя бы одно фото.`
- `Серийный номер уже есть в другой записи.`
- `Поле "Год выпуска" должно быть числом.`

## 8. Производительность Интерфейса

- Список центра всегда открывается с пагинацией.
- Фильтры применяются без полной перезагрузки страницы через HTMX.
- Длинные операции экспорта показывают состояние выполнения.
- Миниатюры фото отдаются отдельными endpoint.
- В таблице показываются только нужные колонки.

## 9. Прототип

Статичный прототип был временным артефактом раннего этапа. После появления рабочих экранов он удалён из приложения и заменён реальными страницами:

```text
/region
/equipment
/equipment/new
```

Эти страницы покрывают два ключевых сценария:

- региональный быстрый ввод;
- центральный реестр с фильтрами и таблицей.

## 10. Источники Для UX-Паттернов

- Snipe-IT: custom fields, fieldsets, asset model binding, display in asset table.
- Snipe-IT: asset labels and QR/barcode-oriented asset lookup.
- BMC Track-It: configurable asset list views, filters, columns, saved views.
- Lansweeper: asset views, custom fields, filters, dashboards.
- Asset Panda обзор: customizable fields, mobile barcode workflows, lifecycle tracking.
