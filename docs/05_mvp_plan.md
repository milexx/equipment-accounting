# План MVP

## Этап 1. Каркас

- создать репозиторий/структуру проекта;
- настроить FastAPI;
- настроить SQLAlchemy 2.0;
- настроить Alembic;
- подключить PostgreSQL;
- добавить базовые шаблоны Jinja2;
- добавить базовый CSS.

## Этап 2. Модель Данных

- миграции для регионов;
- миграции для типов оборудования;
- миграции для полей типов;
- миграции для оборудования;
- миграции для фото;
- миграции для audit log.

## Этап 3. Авторизация MVP

- `AuthProvider`;
- `DatabaseAuthProvider`;
- простой вход/токен;
- проверка доступа региона к своим записям;
- доступ центра ко всем записям.

## Этап 4. Типы И Поля

- список типов оборудования;
- создание/редактирование типа;
- добавление/редактирование динамических полей;
- валидация кода поля;
- выключение поля без удаления исторических данных.

## Этап 5. Оборудование

- список оборудования с пагинацией;
- фильтры по базовым полям;
- форма создания;
- динамическая форма по выбранному типу;
- редактирование;
- карточка оборудования;
- audit log.

## Этап 6. Фото

- `PhotoStorage`;
- `FilesystemPhotoStorage`;
- загрузка 1-5 фото;
- ограничение размера;
- проверка формата;
- генерация превью;
- авторизованная выдача фото;
- удаление фото при удалении оборудования.

## Этап 7. Фильтрация И Экспорт

- фильтрация по динамическим полям;
- контроль индексов для `filterable` полей;
- экспорт CSV/XLSX;
- ограничение 10 000 записей;
- при необходимости асинхронный экспорт.

## Этап 8. Приёмка MVP

- тестовые данные на 100 000+ записей;
- проверка пагинации;
- проверка доступа регионов;
- проверка удаления фото;
- проверка времени ответа списка;
- документация для разработчика и администратора.

## Основные Риски

- неопределённая модель ролей;
- слишком свободные JSONB-фильтры без индексов;
- рассинхронизация БД и файловой системы фото;
- отсутствие audit log;
- слишком сложная форма динамических полей для региональных пользователей;
- экспорт больших объёмов в синхронном запросе.
