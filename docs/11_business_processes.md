# Бизнес-Процессы Системы

Документ описывает бизнес-процессы, которые должна реализовать система учёта неиспользуемого оборудования.

## 1. Общая Карта Процессов

Система ведёт не всё имущество организации, а оборудование, которое больше не используется в регионах и должно пройти дальнейшее решение.

```text
Выявление неиспользуемого оборудования
        |
        v
Ввод данных регионом
        |
        v
Проверка данных центром
        |
        +--> Возврат на доработку
        |
        +--> Диагностика
        |
        +--> Нерабочее -> списание -> утилизация
        |
        +--> Рабочее -> оценка -> подготовка к продаже -> продажа / магазин
```

## 2. Роли

### Регион

Отвечает за первичный ввод:

- находит неиспользуемое оборудование;
- создаёт карточку;
- заполняет базовые поля;
- указывает состояние;
- описывает поломки, если оборудование нерабочее;
- прикладывает фото;
- отправляет запись в центр.

### Центр

Отвечает за контроль и решение:

- проверяет полноту и качество данных;
- возвращает записи на доработку;
- подтверждает состояние;
- отправляет на диагностику;
- направляет нерабочее оборудование на списание/утилизацию;
- направляет рабочее оборудование на оценку/продажу;
- ведёт контроль больших объёмов через фильтры, очереди и экспорт.

### Оценщик / Ответственный За Продажу

Может быть отдельной ролью в будущем. В MVP функции выполняет центр.

Отвечает за:

- оценочную стоимость;
- цену продажи;
- описание для продажи;
- решение о публикации в будущем магазине.

## 3. Процесс 1. Первичный Ввод Регионом

### Цель

Быстро и без обучения завести карточку неиспользуемого оборудования.

### Участник

Регион.

### Вход

Фактически найденное оборудование, которое не используется.

### Шаги

1. Регион нажимает `Добавить оборудование`.
2. Выбирает тип оборудования.
3. Заполняет базовые поля: наименование, инвентарный номер, серийный номер, комментарий.
4. Указывает местонахождение: площадка, склад, кабинет, стойка или другое физическое место.
5. Указывает состояние: рабочее, нерабочее, нужна диагностика.
6. Заполняет динамические поля выбранного типа.
7. Прикладывает 1-5 фото.
8. Если оборудование нерабочее, описывает поломку и прикладывает фото дефекта.
9. Сохраняет черновик или отправляет на проверку.

### Выход

Карточка оборудования в статусе:

- `draft`, если сохранён черновик;
- `submitted`, если отправлено в центр.

### Контрольные Правила

- Нельзя отправить запись без обязательных полей.
- Нельзя отправить запись без минимум одного фото.
- Для нерабочего оборудования нельзя отправить запись без описания поломки.
- Для нерабочего оборудования нужно минимум одно фото типа `defect`.

## 4. Процесс 2. Проверка Центром

### Цель

Проверить, что данные пригодны для принятия решения.

### Участник

Центр.

### Вход

Карточки в статусе `submitted`.

### Шаги

1. Центр открывает очередь `Новые на проверку`.
2. Проверяет базовые поля, фото, состояние и динамические поля.
3. При необходимости возвращает запись на доработку с комментарием.
4. Если данных достаточно, принимает запись.
5. После принятия выбирает дальнейший маршрут: диагностика, списание, оценка, продажа.

### Выход

Один из статусов:

- `needs_revision`;
- `accepted`;
- `diagnostics_required`;
- `writeoff_review`;
- `valuation_pending`;
- `sale_ready`.

### Контрольные Правила

- Возврат на доработку требует комментарий центра.
- Принятие фиксируется в audit log.
- Смена маршрута фиксируется в audit log.

## 5. Процесс 3. Доработка Регионом

### Цель

Исправить неполные или некорректные данные.

### Участник

Регион.

### Вход

Карточка в статусе `needs_revision`.

### Шаги

1. Регион видит список записей на доработке.
2. Открывает замечание центра.
3. Исправляет поля или фото.
4. Повторно отправляет запись на проверку.

### Выход

Статус `submitted`.

### Контрольные Правила

- Регион видит только свои записи.
- История доработок сохраняется.

## 6. Процесс 4. Диагностика

### Цель

Уточнить состояние оборудования, если регион или центр не могут принять решение сразу.

### Участник

Центр, регион или ответственный диагност.

### Вход

Карточка в статусе `diagnostics_required`.

### Шаги

1. Центр помечает запись как требующую диагностики.
2. Указывается причина диагностики.
3. После диагностики фиксируется результат.
4. Оборудование классифицируется как рабочее или нерабочее.
5. Центр выбирает дальнейший маршрут.

### Выход

Один из маршрутов:

- списание/утилизация;
- оценка/продажа;
- возврат на доработку.

## 7. Процесс 5. Списание Нерабочего Оборудования

### Цель

Подготовить нерабочее оборудование к списанию.

### Участник

Центр.

### Вход

Оборудование с состоянием `broken`.

### Шаги

1. Центр открывает очередь `К списанию`.
2. Проверяет описание поломки.
3. Проверяет фото дефекта.
4. Принимает решение о списании.
5. Фиксирует основание списания.

### Выход

Статус:

- `writeoff_review`;
- `writeoff_approved`.

### Контрольные Правила

- Нельзя согласовать списание без описания поломки.
- Нельзя согласовать списание без фото дефекта.
- Решение фиксируется в audit log.

## 8. Процесс 6. Утилизация

### Цель

Закрыть жизненный цикл списанного оборудования.

### Участник

Центр.

### Вход

Оборудование в статусе `writeoff_approved`.

### Шаги

1. Центр переводит запись в `disposal_pending`.
2. После фактической утилизации фиксирует результат.
3. При необходимости прикладывает подтверждающие документы или фото.

### Выход

Статус `disposed`.

### Контрольные Правила

- Утилизация должна быть связана с ранее согласованным списанием.
- Все действия фиксируются в audit log.

## 9. Процесс 7. Оценка Рабочего Оборудования

### Цель

Определить цену оборудования, которое можно продать.

### Участник

Центр / оценщик.

### Вход

Рабочее оборудование, направленное на оценку.

### Шаги

1. Центр открывает очередь `На оценку`.
2. Проверяет состояние, комплектность и фото.
3. Указывает оценочную стоимость.
4. Указывает рекомендованную цену продажи.
5. При необходимости добавляет комментарий к оценке.

### Выход

Статус:

- `valuation_pending`;
- `valued`;
- `sale_ready`.

### Контрольные Правила

- Нельзя перевести в `sale_ready` без цены продажи.
- Изменение оценки фиксируется в audit log.

## 10. Процесс 8. Подготовка К Продаже

### Цель

Подготовить рабочее оборудование к публикации в будущем магазине или продаже другим способом.

### Участник

Центр / ответственный за продажу.

### Вход

Оборудование в статусе `valued` или `sale_ready`.

### Шаги

1. Центр проверяет главное фото.
2. Заполняет описание для продажи.
3. Проверяет цену.
4. Проверяет комплектность.
5. Отмечает готовность к публикации.

### Выход

Статус:

- `sale_ready`;
- `listed_for_sale`.

### Контрольные Правила

- Нельзя публиковать без цены.
- Нельзя публиковать без описания для продажи.
- Нельзя публиковать без фото.
- В будущий магазин попадают только записи `listed_for_sale`.

## 11. Процесс 9. Продажа

### Цель

Зафиксировать факт продажи оборудования.

### Участник

Центр / ответственный за продажу.

### Вход

Оборудование в статусе `listed_for_sale`.

### Шаги

1. Фиксируется покупатель или канал продажи, если это предусмотрено.
2. Фиксируется итоговая цена.
3. Запись переводится в статус `sold`.

### Выход

Статус `sold`.

### Контрольные Правила

- Продажа возможна только для опубликованного или готового к продаже оборудования.
- Итоговая цена фиксируется в audit log.

## 12. Процесс 10. Управление Типами И Полями

### Цель

Дать центру возможность менять состав собираемых данных без разработки.

### Участник

Центр.

### Шаги

1. Центр создаёт тип оборудования.
2. Добавляет поля типа.
3. Настраивает обязательность, порядок, фильтруемость.
4. Проверяет форму в предпросмотре.
5. Включает тип для регионов.

### Контрольные Правила

- Нельзя удалить тип, если по нему есть записи.
- Нельзя физически удалить поле, если по нему есть данные.
- Можно выключить поле или тип.

## 13. Процесс 11. Экспорт И Контроль Качества

### Цель

Позволить центру управлять большим объёмом данных и выгружать нужные выборки.

### Участник

Центр.

### Шаги

1. Центр выбирает представление или фильтры.
2. Проверяет список.
3. При необходимости выполняет массовые действия.
4. Запускает экспорт.

### Выход

XLSX/CSV-файл с текущей выборкой.

### Контрольные Правила

- Экспорт учитывает фильтры.
- Синхронный экспорт ограничен 10 000 записей.
- Большой экспорт должен быть асинхронным.

## 14. Очереди Центра

Центральный реестр должен поддерживать рабочие очереди:

- `Новые на проверку`;
- `Требуют доработки`;
- `Требуют диагностики`;
- `К списанию`;
- `К утилизации`;
- `На оценку`;
- `Готово к продаже`;
- `Опубликовано`;
- `Продано`;
- `Архив`.

Очереди реализуются через сохранённые представления: фильтры, колонки, сортировка.

## 15. Audit Log

Все бизнес-значимые действия фиксируются:

- кто сделал;
- когда;
- что изменилось;
- старое значение;
- новое значение.

Audit log нужен для контроля спорных ситуаций, промышленной эксплуатации и восстановления контекста решений.
